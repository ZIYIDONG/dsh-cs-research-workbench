## 0. 全站骨架（五页共用）

### 0.1 布局

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 科研工作台   [TODO] Project  Paper Library  Idea  Knowledge Base    🔍 ⌘K  ⚙ │
├───────────────┬──────────────────────────────────────────────┬───────────────┤
│ 左侧筛选栏     │ 主内容区                                      │ 右侧助手       │
│ 220px         │ 顶部工具栏 + 列表/画布/看板                    │ 320px，可收起  │
│ 视图/项目/标签 │                                              │ 对话 + 回执    │
├───────────────┴──────────────────────────────────────────────┴───────────────┤
│ 状态条：今日 3/7 · 连续 12 天 · 模型 ok · 同步：本地已保存 · [撤销] 剩余 8 步   │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **最小宽度 1024**；<1180 时右侧助手改为覆盖式抽屉；<1024 左侧筛选栏收起为抽屉（v1 只保证桌面宽度）。
- 页签切换不刷新页面，保留各页滚动位置与筛选；切页不重新拉 `/state`（5 秒轮询 + 写操作后乐观更新）。
- 数据加载：进入页面先渲染骨架屏，`GET /state` 返回后填充；写操作先本地乐观更新，失败回滚并 toast。

### 0.2 共用组件

| 组件 | 行为 |
|---|---|
| `Chip` | 标签/状态小胶囊，颜色由维度决定；点击=按该标签筛选，`×` 移除 |
| `FacetSelect` | 维度下拉，多选，显示已选数量；固定在左侧栏顶部 |
| `Drawer` | 右侧滑出详情面板，宽 420，Esc 关闭，`⌘Enter` 保存 |
| `Modal` | 居中弹窗（导入、生成预览、确认），宽 560/720 两档 |
| `ConfirmGate` | 覆盖/删除类操作必须二次确认；删除只进 `.trash`，文案写明"可从回收站恢复" |
| `Toast` | 底部居中，3 秒消失；错误停留 6 秒并提供「重试」 |
| `EmptyState` | 图标 + 一句说明 + 主按钮 + 2 条示例动作 |
| `SampleBanner` | 顶部黄色条：`这是示例数据，点此清空`（`sampleCleared=false` 时显示） |
| `UndoBar` | 状态条右侧，显示 `撤销 <动作名>`，`⌘Z` 触发 |
| `AssistantPanel` | 对话流 + 结构化回执卡片（"已创建 2 个任务 · 已改期 1 条"）+ 撤销按钮 |

### 0.3 快捷键

| 键 | 作用 |
|---|---|
| `⌘K` | 命令面板：新建任务/项目/文献/想法/笔记、切页、运行生成、搜索 |
| `N` | 当前页新建（聚焦快速输入） |
| `/` | 聚焦搜索框 |
| `⌘Z` / `⌘⇧Z` | 撤销 / 重做（只做撤销，重做 v1 不做） |
| `⌘Enter` | 提交当前输入/保存抽屉 |
| `Esc` | 关抽屉/弹窗/命令面板 |
| `G` 然后 `T/P/L/I/K` | 跳转五页（TODO/Project/Paper/Idea/KB） |

### 0.4 通用交互约定

1. 所有写操作走同一个 `POST /ops`；成功返回 `{receipts[], state?, canUndo}`，客户端用返回的 state 片段更新。
2. 失败不整批回滚（逐条 `errors`），toast 显示"3 条成功、1 条失败：<原因>"。
3. 拖拽（任务改期、卡片挪列、里程碑改期）先乐观更新，失败回滚并提示。
4. 每个空状态都提供"载入示例"和"从零开始"；示例数据带 `sample:true`，清空示例不碰真实数据。
5. 模型不可用时：助手输入框仍可用，返回 `engine:"local"` 与"本地规则"标记；一键生成按钮置灰并提示原因，不弹错误框。

## 1. TODO（默认落地页）

> **首页默认视图是「散落」**：直接仿照 dsh-media-desk 首页（首屏一句话 + 一句话记录 + 散落卡片墙 + 底部 dock + 右侧助手），同一页另有「列表」「日历」两种模式。像素级规格、交互常量与验收见 [dsh-research-desk-home.md](dsh-research-desk-home.md)。本节 1.2 起描述的线框与行为作为「列表模式」保留。

### 1.1 目标

回答"今天该干什么"：3 秒内看清今日三件事，10 秒内把想到的事记下来并带正确的截止/项目。

└────────────────┘└────────────────────────────────────────────┴────────────────┘

### 1.3 区域与行为

**快速添加（主区顶部，常驻）**
- 输入框 + 回车即建；解析不成功也建（标题=原文，不带 due/project），绝不报错。
- 解析规则（本地 `intents.js`，不调模型）：
  - 日期：今天/明天/后天/周X/下周X/`11/20`/`11-20`；"下午/上午/晚上"→ 时段提示（不写具体时刻）。
  - 项目：`@项目名`（前缀匹配，命中即带 `projectId`）。
  - 优先级：`#P0`–`#P3` / `!1`–`!4`。
  - 估算：`~30m / ~2h / ~1d` → `estimate`（分钟）。
  - 标签：`#标签`（已注册标签直接带；未注册建 `dimension:'free'`）。
- 建完输入框清空并保留焦点，下方列表插入新行并高亮 1 秒。
- 支持多行粘贴：每行一条任务。

**今日三件事**
- 规则：`逾期` > `P0` > `今日到期` > 所属项目 `nextDeadline` 最近；最多 3 条。
- 手动 pin：任务行右侧「📌」置顶，最多 3 条；pin 覆盖推荐。
- 完成一条自动补位下一条，并 toast"已补位：<下一条>"。

**任务行**
- 勾选框：`status` todo/doing → done（记 `doneAt`，更新 metrics）；done → todo（恢复）。
- 单击行：打开右侧 Drawer（标题、备注、截止、项目、优先级、标签、估算、关联文献/想法）。
- 行内 chips：项目、优先级、截止、标签（最多 3 个，其余 `+n`）。
- 行尾动作（hover 出现）：`▶ 开始`（doing）、`📌`、`⇗ 升级为项目`、`✂ 拆解`、`⋯`（改期/改优先级/删除→trash）。
- 双击标题：就地编辑；失焦保存。
- 拖拽：拖到日历某天→`schedule_todo`；拖到左侧项目→改 `projectId`；拖到"等待中"→ `status=waiting`。

**视图**
- 今日：due ≤ 今天，含逾期与 doing，按 逾期→P0→时间 排序。
- 本周：本周一到周日，按天分组。
- 全部：未完成，按项目分组（无项目归"收件箱"）。
- 等待中：`status=waiting`，按 `blocked` 标签分组（等数据/等回复/等机器/等合作者/等设备）。
- 已完成：按 `doneAt` 倒序，按天分组，可一键"归档已完成的旧任务"（v1 不删，只折叠）。

**日历（右侧 300px 可收起）**
- 默认周视图（周一–周日），每天显示当天任务数圆点（红色=有逾期，实心=有任务）。
- 点某天→过滤主区为该天；拖任务到某天→改期；点"+"→在当天快速添加。

**复盘条（主区底部固定）**
- 本周完成数/创建数、逾期数、连续完成天数、专注时长（手动录入入口）。
- 点击展开 7 天柱状图（来自 metrics），对比上周显示 ▲▼。

### 1.4 数据映射

| 界面 | 字段 |
|---|---|
| 三件事 | `todos` 过滤 + pin 列表（设置在 settings.pinnedTodoIds） |
| 行 chips | `projectId→projects.name`、`priority`、`due`、`tags[]`、`estimate` |
| 日历点 | 按 `due` 分组计数 |
| 复盘条 | `metrics` 最近 7 天 + `todos.doneAt` |

### 1.5 状态

| 状态 | 表现 |
|---|---|
| 空（无任务） | `EmptyState`："今天还没有任务"＋主按钮「添加第一件事」＋两条示例（"明天下午读一篇论文"「查看示例数据」） |
| 加载 | 三行骨架行 + 日历骨架格 |
| 失败 | 主区错误块「状态读取失败」+ 重试；顶部保留离线提示，禁止写入 |
| 全部完成 | 主区顶部庆祝条："今日 7/7 完成"，不弹窗不撒花 |

### 1.6 AI 入口

- 助手示例："把今天没做完的推到明天"（批量 `schedule_todo`）、"这周实验类任务有几天"（查询回执）、"帮我把写引言拆成 3 步"（`produce: todo-breakdown`，预览后确认写入）。
- 生成结果先出预览卡片（可编辑标题/日期/优先级），「全部添加」才落库。

### 1.7 验收标准

1. 输入 `明天下午跑消融实验 @NeuSym ~2h` 建任务后：`due=明天`、`projectId=NeuSym`、`estimate=120`，输入框清空。
2. 勾选完成→metrics 当日 `todosDone+1`，状态条与复盘条同步更新。
3. 拖任务到周三→`due` 改为周三，撤销一步恢复。
4. 三件事 pin 3 条后不再自动推荐；取消 pin 恢复推荐。
5. 断网/接口失败时写入被阻止且有明确提示，不出现半写状态。

## 2. Project

### 2.1 目标

把"一个研究目标"变成可跟踪的容器：进度、里程碑、产出、健康度、一键周报。

### 2.2 线框

```
┌ 项目列表 260px ──────┐┌ 详情 ────────────────────────────────────────────────┐
│ [＋ 新建项目]         ││ NeuSym：神经符号漏洞检测         ● active  🟢 健康 68 │
│ ┌──────────────────┐ ││ 目标：在 3 个真实固件上做到 90% 召回…        [编辑] │
│ │NeuSym  ● 🟢 68%  │ ││ ── 概览 │ 看板 │ 里程碑 │ 产出 ──────────────────── │
│ │里程碑 2/5 · 12/01│ ││ 下一步：                                              │
│ └──────────────────┘ ││ ☐ P0 跑消融实验（今天）  ☐ P1 补对比表（周四）        │
│ ┌──────────────────┐ ││ 健康度分解                                            │
│ │综述  ● 🟡 40%     │ ││ 完成率 62% · 逾期 1 · 里程碑偏差 +3 天 · 近 7 天 14 项 │
│ └──────────────────┘ ││ ───────────────────────────────────────────────────── │
│ 已结项 ▸ (3)         ││ 最近活动：完成"跑基线" · 新增文献 2 篇 · 更新里程碑   │
└──────────────────────┘│ [生成项目计划] [生成周报] [结项总结]                   │
                        └───────────────────────────────────────────────────────┘
```

### 2.3 区域与行为

**项目列表（左 260px）**
- 卡片：名称、状态点、健康度百分比环、`里程碑 done/total`、`nextDeadline`。
- 排序：进行中在前，按 `nextDeadline` 升序；已结项折叠组。
- 右键菜单：编辑、暂停、归档、删除（→trash，需确认）。
- 顶部「＋ 新建项目」→ 抽屉表单：名称、目标、起止、类型（`type` 标签）、投稿目标（`venue`）、敏感级别（`sensitivity`）、成员。

**详情头部**
- 名称可就地编辑；状态切换 active/paused/done；健康度徽章点击展开分解。
- 目标一行截断，点击展开全文（Markdown 渲染）。
- 操作：「编辑」打开抽屉；「⋯」→ 归档/删除/导出 Markdown。

**Tab 1 概览**
- 下一步：该项目未完成、未逾期任务中按优先级取 3 条；点击可完成。
- 健康度四指标卡：完成率（done / 全部关联任务）、逾期数、里程碑偏差（实际完成日 − 计划日，均值）、近 7 天活动量（任务完成+笔记+文献）。
- 健康色：绿=无逾期且偏差≤0；黄=逾期≤1 或偏差≤7 天；红=逾期≥2 或偏差>7 天。
- 最近活动流：最近 20 条（任务完成、里程碑完成、文献关联、想法升级），点击跳转。
- 底部生成按钮：`生成项目计划`（produce: project-plan）/`生成周报`（同 target，参数 period=week）/`结项总结`。

**Tab 2 看板**
- 四列：待办 / 进行中 / 等待中 / 已完成。列头显示数量与 WIP 提示（进行中 >5 变黄）。
- 卡片：标题、优先级、截止、标签、负责人（members）。
- 拖拽跨列 → `update_todo.status`；拖到列内 → 重排（v1 只改状态不排序）。
- 卡片菜单：编辑、改期、移到项目（其他项目）、删除。
- 右上「＋」快速建任务，自动带 `projectId`。

**Tab 3 里程碑**
- 横向时间线：节点圆点 + 标题 + 计划日期；已完成实心，逾期红色描边。
- 拖节点改日期 → `update_milestone`；点圆点勾选完成（记 `doneAt`）。
- 「＋ 里程碑」内联输入：标题 + 日期。
- 时间线下方：距离下一里程碑倒计时 + 关联任务数。

**Tab 4 产出**
- 论文：关联 `paperIds` 的卡片，点击跳 Paper Library。
- 实验：`experimentIds`（v1 只记元数据：名称、日期、配置摘要、指标、结论），「＋ 记录实验」抽屉表单。
- 仓库：`repos[]` 链接列表，点击用系统浏览器打开（不 clone）。
- 导出：当前项目 Markdown（目标/里程碑/任务/产出）到 vault。

### 2.4 生成物预览

- 三者共用 `Modal`：左侧大纲（可折叠章节），右侧 Markdown 预览，底部「重新生成本节」「保存到 vault」「复制」。
- 保存路径默认 `<vault>/Research/Projects/<项目名>/<类型>-<日期>.md`；保存后记录 `savedPath`。
- 无模型：按钮置灰，tooltip"未配置助手模型"；计划包可用本地模板生成（里程碑建议按类型给默认 3 条）。

### 2.5 状态

| 状态 | 表现 |
|---|---|
| 无项目 | `EmptyState`："还没有项目" + 「从想法升级」「新建项目」「载入示例」 |
| 项目无任务 | 概览显示引导："从看板添加第一个任务" |
| 生成中 | 按钮转圈 + 进度条（planning/drafting），可取消 |
| 生成失败 | Modal 内错误 + 重试，不关闭已有编辑内容 |

### 2.6 验收标准

1. 新建项目后出现在列表、可选为任务归属；删除后关联任务 `projectId` 置空（不删任务）。
2. 看板拖动任务→状态变化，概览完成率同步，撤销可回退。
3. 里程碑改期→偏差与健康色变化。
4. 周报生成预览可编辑，保存后文件出现在 vault 约定目录。
5. 健康度四指标与底层数据手算一致。

### 3.3 区域与行为

**表格视图（默认）**
- 列：勾选、标题（含 arxiv/DOI 图标）、作者（前 3 + et al.）、年份、venue、状态、深度、关系、评分、标签、笔记数、添加日期。
- 列头排序（标题/年份/评分/添加日期）；行密度三档（紧凑/标准/宽松），记住设置。
- 行单击→右侧 Drawer 详情；勾选→底部批量条（对比表、related work、打标签、改状态、导出、删除→trash）。
- 虚拟滚动：1000 篇不卡（固定行高 56px，按窗口切片渲染）。

**卡片视图**
- 2–3 列瀑布流：标题、作者年份 venue、摘要 3 行截断、我的 tags、评分、状态色条。
- 卡片底部快捷动作：开始读、写笔记、对比（加入对比篮）。

**导入（Modal）**
- Tab：`DOI/arXiv` / `BibTeX` / `Zotero`。
- DOI/arXiv：粘贴后解析 DOI 或 arXiv id → 通过 Crossref / arXiv 公开 API 拉元数据（HTTPS、10s、2MB）；失败则建"待补全"卡（标题=输入，status=inbox，标记 `needsMetadata`）。
- BibTeX：粘贴多条目→解析（`bridge/bibtex.js`）→预览列表→确认导入。
- Zotero：输入关键词调本机 API 只读搜索（`/users/0/items?q=`），结果显示条目 key/标题/作者→选择导入；Zotero 未运行→明确文案"Zotero 未启动或未开启本机 API"，不阻塞其他 Tab。
- 去重：DOI 精确、arXiv id 精确、`title+year` 归一化后相似度 ≥0.9；命中时提示"已存在《…》，合并/跳过/仍然导入"。
- 导入后默认 `status=inbox`，标签落 `source` 维度待确认区。

**详情 Drawer**
- 上半：标题（可编辑）、作者、年份、venue、DOI/arXiv/URL（可点开）、摘要（折叠）。
- 中部：状态流按钮（inbox→reading→read→cited）、深度、关系、竞争、评分（★）、标签编辑（facet 选择器）。
- 下部：我的摘要/批注（多行，失焦保存）、笔记列表（`noteIds` → KB，可新建）、关联项目/想法。
- 底部：「生成对比」「写 related work」「导出 BibTeX」。

**对比表（Modal，批量）**
- 列：论文、方法、数据集、指标、主要结论、局限、与我的关系、可复现性。
- 单元格可编辑（保存到 `papers[i].compare`），支持从摘要 AI 预填（有模型时，标注"AI 预填，请核对"）。
- 导出 Markdown 表格到 vault，或复制到剪贴板。

**related work 段落**
- 选中 2–8 篇 → produce: paper-review → 生成带引用的段落，`[[cite:KEY]]` 占位可点击；预览可编辑后保存到 vault。

**导出**
- BibTeX / CSL-JSON：选中或筛选结果全量；文件写 `<vault>/Research/Papers/export-<日期>.bib`；提示"可直接导入 Zotero"。

### 3.4 数据映射

`status`→左栏计数；`tags` 中 `depth/rel/竞争/repro/cite/venue/area` 分别渲染为 chip 并可按 facet 筛选；`rating` 星级；`noteIds` 计数。

### 3.5 状态

| 状态 | 表现 |
|---|---|
| 空库 | `EmptyState`：「粘贴 DOI 或 arXiv 链接开始」＋「从 Zotero 导入」＋「载入示例」 |
| 无搜索结果 | "没有匹配的文献，清除 3 个筛选"＋「清除筛选」 |
| Zotero 不可用 | Zotero Tab 内联错误 + "重试"，其他 Tab 正常 |
| 元数据抓取失败 | 卡片黄色标记「元数据待补全」，点击可手填 |
| 批量操作部分失败 | 底部批量条提示"2 篇成功、1 篇失败"，失败项保持选中 |

### 3.6 验收标准

1. 粘贴 arXiv 链接→建卡并带标题/作者/年份；重复导入提示已存在。
2. Zotero 未启动时点 Zotero Tab 显示明确错误，其他功能不受影响。
3. 选 3 篇生成对比表→表格可编辑→导出 Markdown 落到 vault。
4. 读一篇→状态 reading→写笔记→KB 出现笔记且 `noteIds` 双向更新。
5. 导出 .bib 可被 Zotero 正常导入（字段完整、无重复 key）。

## 4. Idea

### 4.1 目标

让"半成品的想法"有地方待着、能被看见、能和别的想法长出关系，并在成熟时一键变成项目/提案/实验计划。

### 4.2 线框（画布视图）

```
┌ 工具栏： [画布|信息流]  [＋ 快速记录一句…]  [聚拢相关]  筛选：领域▾ 性质▾ 成熟度▾ ┐
├──────────────────────────────────────────────────────────────────────────────────┤
│   ┌─ 假设 H ──────┐        ┌─ 问题 Q ─────┐          ┌─ 方法 M ──────────┐      │
│   │ 符号执行+LLM   │◄──────►│ 如何验证语义  │          │ 用差分测试做      │      │
│   │ 生成测试输入   │  相关  │ 等价改写？    │          │ 固件漏洞定位      │      │
│   │ 探索中 ★4     │        │ 种子 ★2       │          │ 探索中 ★3  竞争?  │      │
│   │ [NeuSym 项目] │        │               │          │                   │      │
│   └───────────────┘        └───────────────┘          └───────────────────┘      │
│            ┌─ 局限 L ──────────┐                                                   │
│            │ 真实设备覆盖率低   │         [双击空白处新建]        [缩放 100%]      │
│            └───────────────────┘                                                   │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 4.3 区域与行为

**快速记录（顶部常驻）**
- 一句话回车建卡：`kind` 默认 idea；识别前缀 `问题:`/`假设:`/`方法:`/`局限:` → 对应 kind。
- 建卡后：若落在画布视图，卡片出现在视口中心偏下；信息流视图插入顶部并高亮。
- `⌘Enter` 新建后保持焦点，支持连续记录。

**画布视图**
- 无限画布：平移（空白拖拽/空格拖拽）、缩放 50%–200%（滚轮 + 按钮），双击空白新建卡。
- 卡片：可拖拽（写 `pos:{x,y}`），尺寸自适应内容；标题 2 行、正文 4 行截断。
- 卡片角落：kind 图标+色、成熟度 chip、评分 ★、关联图标（文献/项目数量）。
- 连线：v1 不做手绘连线；"相关"用虚线自动连接（相关度 ≥ 阈值，最多 3 条），点击虚线显示相关原因（共同标签/关键词/关联同一文献）。
- 「聚拢相关」：按标签+关键词做简单聚类，把互相相关的卡片摆到相邻位置（一次性布局动画，可撤销）；不做力导向持续动画。
- 双击卡片→打开右侧 Drawer；拖到左侧栏某项目→关联 `projectId`。

**信息流视图**
- 按 `createdAt` 倒序，按周分组；每条：kind、标题、正文摘要、标签、成熟度、评分、来源（哪篇文献/哪次会议）。
- 顶部按 kind/成熟度/领域筛选；支持"只看未处理"（status=seed）。

**详情 Drawer**
- 标题/正文编辑（Markdown 基础）、kind 切换、成熟度、评分、标签、关联文献（搜索选择）、关联项目、`horizon/evidence/cost` 标签。
- 显示"相关想法"3 条（同标签/同文献/关键词），点击跳转。
- 底部动作：`升级为项目`、`生成研究提案`、`生成实验计划`、`归档（parked）`、`删除→trash`。

**升级为项目（向导，3 步）**
1. 基本信息：项目名（默认想法标题）、目标（默认正文）、类型/阶段默认（`stage=设计`）。
2. 里程碑建议：按 `type` 给 3 条模板（如论文：调研→实现→实验→写作），可删改。
3. 首批任务：AI 或本地模板生成 3–5 条（带优先级），可编辑；确认后 `promote_idea_to_project` 一次性建项目+任务，想法 `status=project` 并 `projectId` 回填。

**生成研究提案**
- 预览 Modal：问题 / 动机 / 相关工作 / 方法 / 预期贡献 / 风险 / 所需资源 / 时间线；可编辑、保存到 `<vault>/Research/Ideas/<想法>.md`。
- 生成实验计划：假设 H1/H0、自变量/因变量、指标、baseline、数据、停止条件。

### 4.4 状态

| 状态 | 表现 |
|---|---|
| 空 | 画布中央提示"双击空白处记录第一个想法" + 3 张示例卡（`sample`） |
| 卡片过多（>80） | 提示可切换信息流或按标签筛选；画布仍可用 |
| 聚类失败 | toast"没有找到明显相关的一组"，不改变布局 |
| 无模型 | 提案/实验计划按钮置灰，升级为项目仍可用模板 |

### 4.5 验收标准

1. 快速记录 `问题: 如何验证语义等价？` → 建卡 `kind=question`，画布与信息流同时可见。
2. 拖动卡片→刷新后位置保持（`pos` 持久化）。
3. 升级为项目→生成 1 个项目 + ≥3 条任务，想法状态变 project 且 `projectId` 正确。
4. 相关卡片虚线连接可点击，显示"共同标签：LLM"之类原因。
5. 提案生成保存后文件出现在 vault，内容含全部小节。

## 5. Knowledge Base

### 5.1 目标

把散落的笔记沉淀成"个人研究方法论"：能查、能链、能复用，最后导出成 agent 可用的 Skill。

### 5.2 线框

```
┌ 笔记树 260px ─────┐┌ 编辑器 ──────────────────────────────────┬ 右栏 300px ────┐
│ 🔍 搜索笔记…       ││ 标题：[[双向链接]] 是怎么实现的？        │ 元数据          │
│ ＋ 新建笔记        ││ [B] [I] [H] [链接] [代码] [公式]         │ 标签：kb:方法论 │
│ ▾ 方法论 (12)      ││ ─────────────────────────────────────── │ verified:已验证│
│   · 如何读一篇论文  ││ ## 要点                                 │ scene:写作     │
│   · 实验设计清单    ││ 双向链接 = 解析 [[名]] → 反查引用…       │ ─────────────── │
│ ▾ 术语表 (8)       ││                                         │ 反向链接 (3)    │
│   · 符号执行        ││ ```ts                                   │ ← 如何读论文    │
│ ▸ 领域知识 (21)    ││ links[] // 由内容解析                   │ ← 知识库设计    │
│ ▸ 写作风格 (5)     ││ ```                                     │ ─────────────── │
│ ▸ 审稿意见 (4)     ││                                         │ 相关笔记        │
│ ▸ 规则 (6)         ││                                         │ · 综述写作模板  │
│ ───────────────    ││                                          │ ─────────────── │
│ vault: Research/…  ││                                          │ [导出 Skill]    │
│ [同步到 vault]     ││                                          │                 │
└────────────────────┘└──────────────────────────────────────────┴─────────────────┘
```

### 5.3 区域与行为

**笔记树（左 260px）**
- 分组：按 `kb` 标签分组（方法论/术语表/领域知识/写作风格/审稿意见/规则），组内按更新时间倒序；支持自定义文件夹（`parentId`）。
- 搜索：标题+正文全文（本地索引，输入 200ms 防抖）；命中高亮。
- 底部 vault 绑定状态：`未绑定` / `Research/Knowledge · 已同步 2 分钟前`；按钮「同步到 vault」（v1 单向导出）。

**编辑器（中）**
- 标题单行 + 正文 textarea（等宽字体，Markdown 源文），右侧实时预览开关（预览用内置轻量渲染：标题/列表/粗斜体/代码块/表格/`[[链接]]`）。
- 工具栏：加粗、斜体、标题、列表、代码块、链接、`[[` 插入笔记链接、概念卡模板、公式（`$…$` 原样渲染）。
- `⌘S` 保存；失焦 1.5 秒自动保存；未保存时标题旁显示圆点。
- `[[` 触发笔记搜索下拉，选中插入 `[[标题]]`；保存时解析 `links[]`，同时更新被链接笔记的反向链接。
- 点击预览中的 `[[链接]]` → 跳转；目标不存在 → 提示"新建《…》"。
- 概念卡模板：插入固定骨架（概念/定义/来源/关联文献/易混点）。

**右栏**
- 元数据：标签编辑（facet）、`verified`、`scene`、`source`、关联文献/项目。
- 反向链接：列出引用本笔记的笔记（`links` 反查），点击跳转。
- 相关笔记：同标签 3 条。
- 历史：最近 5 个版本时间点（从 state 的 note history，保留 20 版）。

**规则页（笔记树「规则」组）**
- 列出 `skills`：名称、规则一句话、证据、置信度、状态（proposed/active/exported）。
- 操作：采纳（→active）、忽略（→dismissed，不导出）、编辑规则文本、导出 Skill。
- 「从笔记/复盘提炼规则」→ produce: kb-rules → 生成 3–5 条候选（带依据），逐条采纳/忽略。
- 导出 Skill：写 `<DSH_HOME>/skills/research-writing/SKILL.md`（YAML frontmatter `name/description`），成功 toast 显示路径；`sample:true` 的规则永不导出。
- 「生成术语表」：把 `kb:术语` 笔记汇总成 Markdown 表格导出。

**vault 同步**
- 设置里绑定 vault 子目录（默认 `Research/Knowledge/`）。
- 导出：每篇笔记 → `<vault>/Research/Knowledge/<分组>/<标题>.md`，带 frontmatter（tags、updatedAt）；冲突时保留 `<名>.local.md` 与 `<名>.remote.md` 双份并提示。
- 导入：扫描目录中带 `dsh-csrw: true` frontmatter 的文件（只认识自己导出的），变更才覆盖，不删 vault 中其他文件。

### 5.4 状态

| 状态 | 表现 |
|---|---|
| 空 | 中央 `EmptyState`："写下第一篇笔记"，模板按钮：如何读论文 / 实验设计清单 / 术语卡 / 载入示例 |
| 未保存冲突 | 保存时发现 mtime 变化 → 提示"文件已被外部修改"，提供「保留我的」「载入磁盘版本」「另存为副本」 |
| vault 未绑定 | 同步按钮置灰，tooltip"先在设置中绑定 Obsidian vault" |
| 导出失败 | toast 错误 + 「打开设置」；不丢当前编辑内容 |

### 5.5 验收标准

1. 新建笔记写入 `[[另一篇]]` 保存后，另一篇的右栏反向链接出现本笔记。
2. 点击预览中的链接可跳转；不存在的链接提示新建并可创建。
3. 规则采纳后导出 Skill，文件生成且 frontmatter 合法，示例规则不在文件中。
4. 绑定 vault 后「同步到 vault」生成对应 .md，frontmatter 含标签；修改后再次同步覆盖自己导出的文件。
5. 术语表导出内容与 `kb:术语` 笔记一致（无重复、按字母/拼音排序）。

## 8. 全局错误与边界

| 场景 | 处理 |
|---|---|
| `/state` 读失败 | 全屏错误页 + 重试；写入按钮禁用；不覆盖本地 state |
| `/ops` 部分失败 | 逐条错误 toast；成功部分保留；可撤销整批（回滚到操作前快照） |
| 生成中关闭页面 | 后台继续；回来可在状态条看到「1 个生成任务」 |
| state.json 被外部改坏 | 启动时 schema 校验失败 → 备份为 `state.corrupt-<时间>.json`，尝试最近备份，失败则进入只读修复模式 |
| 多窗口同时写 | mtime 变化 → 合并前重读；冲突字段以后写为准并 toast"内容已被其他窗口更新" |
| 粘贴超长文本 | 正文截断到 40000 字符并提示 |
| 上传超限 | 单文件 >50MB 拒绝并提示上限 |
